## 1. Цель задачи

Получить программный доступ к данным AmoCRM по TG-рассылкам, чтобы заменить
ежедневный ручной сбор цифр с дашборда на автоматическую выгрузку. По
фильтру **«бот × дата»** наш сервис `senler-salebot-metrics` должен
получать тройку: **кол-во лидов / кол-во неликвида / кол-во оплат ОП** —
с логикой фильтров, идентичной текущему дашборду аналитики, чтобы цифры
совпадали с ручным сбором.

## 2. Описание задачи

**Контекст.** В школе сейчас ежедневно руками снимаются метрики по
TG-рассылкам: открывается дашборд аналитики в AmoCRM, ставится фильтр по
дате, выписываются три числа — лиды, неликвид, оплаты ОП — и переносятся
в общую сводку. Это нужно автоматизировать: параллельно мы пишем сервис
`senler-salebot-metrics`, который раз в сутки в 07:00 Мск собирает метрики
самих рассылок (Senler по ВК, Salebot по TG) и связывает их с заявками
AmoCRM. Запись идёт в Google Sheets.

**Что нужно от отдела аналитики.** Способ получать те же три числа
программно по двум параметрам — `дата` и `бот Salebot`. Формат отдачи на
выбор аналитики, что им удобнее:

1. Read-only доступ к Postgres + SQL/вью с эталонными фильтрами;
2. HTTP-endpoint `GET /metrics?bot=<id>&date=YYYY-MM-DD` → JSON;
3. Лист в Google Sheets, в который их сервис ежедневно пишет срез с
   ключом `(дата, бот)`.

**Эталон.** Текущий дашборд аналитики, с которого снимаются цифры сейчас.
Логика фильтров (этапы воронки, теги, статусы, ответственные) должна
совпадать 1-в-1, чтобы цифры сходились.
